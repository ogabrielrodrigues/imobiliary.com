Imobiliary API

The service behind the rental management platform: identity and the office, the account holder's rights under the LGPD, and the office's register of people and properties.

base http://127.0.0.1:8081 format application/json ids UUIDv7 instants RFC 3339 contract openapi.yaml

Authentication

Data belongs to an office. An account works in one office at a time, as admin or member, and may belong to several. A session is two credentials.

  • The access token is a JWT signed with Ed25519, valid for 15 minutes, sent as Authorization: Bearer. The membership behind it is read again on every request, so a role change or a removal applies at once. A token minted before the last password change is refused.
  • The refresh token is an opaque secret, spent once at POST /v1/sessions/refresh. Presenting a spent one ends every session of the account: two parties hold it, and the owner cannot be told from the thief. Share one refresh between concurrent calls.
POST /v1/sessions
{ "email": "ana@example.com", "password": "uma senha bem longa" }

200 { "mfa_required": true, "challenge": "…", "challenge_expires_at": "…", "organizations": […] }

Second factor

TOTP per RFC 6238: 30-second steps, 6 digits, SHA-1. Optional for a member, mandatory for an administrator.

For an account with it, signing in answers with a challenge. POST /v1/sessions/mfa completes it with a code from the app or a recovery code. A challenge lasts five minutes and allows one attempt, right or wrong.

An administrator who has not enrolled receives a session flagged mfa_enrollment_required. It reaches only the enrolment endpoints, the export and the deletion. Everything else answers 403 mfa_enrollment_required.

Office data

People belong to the office the session works in, and every member may manage them. Each request runs in a transaction scoped to that office under forced row-level security, so another office's rows answer 404, as a missing row does.

Email, phone, CPF, CNPJ and birth date are encrypted at rest. A CPF or CNPJ is still found exactly, through an index scoped to the office.

Edits are optimistic. A read returns the version in ETag; PUT sends it back in If-Match. Without it the answer is 428; with a version that is no longer current, 412. Read again and redo the edit.

PUT /v1/people/0193…
If-Match: "3"

412 { "error": { "code": "precondition_failed", "message": "…" } }

Errors

Every failure has one shape. Branch on code; message is prose and may change. fields lists every refused input at once.

{ "error": { "code": "validation_failed", "message": "…",
             "fields": [ { "field": "password", "message": "is required" } ] } }
StatusCodeMeans
400bad_requestMalformed JSON, duplicate member names or trailing data. Unknown members are ignored.
401unauthorizedOne answer for a refused token, a wrong password or code, a spent or unknown link, a reused session.
403forbiddenNot allowed, or not a member of that office.
403mfa_enrollment_requiredEnrol a second factor first.
404not_foundNo such resource in this office.
409conflictThe current state forbids it, such as a pending invitation for the same address.
409in_useA delete refused because other records still link to it.
412precondition_failedThe record changed since it was read.
413payload_too_largeBody over 1 MiB.
415unsupported_media_typeSend application/json.
422validation_failedRead and refused; see fields.
428precondition_requiredSend If-Match with the version being edited.
429rate_limitedWait Retry-After seconds.
500internal_errorLogged with the request id; nothing leaks.

Registration and password recovery answer 202 whether or not the address has an account. Telling those apart is what an attacker would be asking.

Rate limits

Three token buckets. Each refusal is 429 with Retry-After in whole seconds, rounded up.

BucketKeyed byRateBurst
Every requestclient address, IPv6 per /6410 / s60
Credentialsclient address1 / 5 s10
Writesaccount2 / s20

Every response carries X-Request-ID, Cache-Control: no-store and X-Content-Type-Options: nosniff. A valid traceparent is carried into the logs.

Privacy

The account holder's rights under LGPD art. 18. Both are reachable before second-factor enrolment, so nobody has to set one up in order to leave.

GET/v1/me/exportbefore enrolment · writes

Art. 18, II. The account, memberships, second-factor state, stored sessions, invitations received, the audit events the account acted in and its access records, oldest first. No password hash, TOTP secret, token or code digest. The export is itself audited.

Answers
200 AccountExport
POST/v1/me/deletionbefore enrolment · credentials · writes

Art. 18, VI, confirmed with the password. Immediate and permanent. A POST with a body because proxies may drop the body of a DELETE.

Body
password
Erased
The account, memberships, sessions, second factor, recovery codes, pending resets. An office whose only member is this account goes with it.
Kept
Access records keep the account id, and its address is kept sealed, for six months (Marco Civil art. 15; LGPD art. 16, I). Audit entries stay without the actor; each office gets user.deleted.
Answers
204 · 401 wrong password · 422 on organizations: the only administrator of an office with other members · 422 on organization_data: the office closing with the account still holds people

People

One entity for owners, tenants, guarantors and representatives: the role lives in the link that uses a person, never in the person. An individual carries a CPF; a company carries a CNPJ, alphanumeric ones included.

GET/v1/peoplesession

Alphabetical, ignoring case and accents. A q that is a valid CPF or CNPJ finds that document exactly; any other q matches a fragment of the name, so joao finds João Silva. Rows carry no sealed field.

Query
q, kind, limit (20, at most 100), cursor
Answers
200 { people, next_cursor } · 422 bad cursor or kind
POST/v1/peoplesession · writes

Registers a person with up to ten addresses, one primary. Naming a spouse writes the link on the spouse's record too; the spouse must be an individual registered as married or in a stable union and not linked to someone else. Representatives must be individuals.

Body
kind, name, email, phone; individuals cpf, nationality, marital_status, property_regime, spouse_id, occupation, birth_date, gender; companies cnpj, trade_name, representative_ids; addresses
Answers
201 Person with ETag · 422, including a CPF or CNPJ already in the office

Properties

A property has one address of its own, its registration numbers and one or more owners. Shares are percentages with up to four decimal places and add up to exactly 100: a property split in three is 33.3333, 33.3333 and 33.3334. The database checks the sum again when the transaction commits.

GET/v1/propertiessession

Ordered by street and number, ignoring case and accents. q matches the street, district or city, the registry or the municipal registration; owner_id keeps what one person owns a share of.

Query
q, owner_id, limit, cursor
Answers
200 { properties, next_cursor }, each with owner_names
