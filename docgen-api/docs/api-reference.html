docgen API Reference

Upload a Word template with {{.placeholder}} markers. The service works out which fields it contains, renders documents against that schema, and serves the finished .docx.

http://localhost:8080
Auth

Quickstart

Four calls take you from nothing to a finished document.

  1. Create an account, then log in to get a token pair.
  2. Upload a .docx. The response tells you which placeholders it found.
  3. Generate a document by supplying a value for each of those placeholders.
  4. Download the result.
# 1. Log in.
curl -X POST localhost:8080/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"someone@example.com","password":"a-sufficiently-long-password"}'

# 2. Upload a template. Attach the .docx as the "file" part.
curl -X POST localhost:8080/v1/templates \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F 'name=Service agreement' \
  -F 'file=@agreement.docx'

# 3. Generate. The keys must match the placeholders exactly.
curl -X POST localhost:8080/v1/documents \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"template_id":"...","data":{"customer_name":"Acme","plan":"Premium"}}'

# 4. Download.
curl -OJ localhost:8080/v1/documents/$ID/download \
  -H "Authorization: Bearer $ACCESS_TOKEN"

Authentication

A session is two credentials with different jobs. The access token is a short-lived JWT you send on every authenticated request. The refresh token is an opaque secret whose only purpose is to obtain the next access token. 

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

The access token is verified without touching the database, which is what keeps it fast — and also why it cannot be revoked before it expires. That is the reason its life is short: 15 minutes by default.

The refresh token is single-use

Every call to /v1/auth/refresh consumes the secret you sent and returns a new one. Store the new pair immediately.

If a spent secret is presented again, two parties are holding it and there is no way to tell the owner from a thief — so every session of that account is revoked, including the successor a legitimate client holds. Losing your session and having to log in again is the intended outcome of that situation.

Passwords are hashed with argon2id. The only rule is length — at least 12 characters — with no composition requirements, following current NIST guidance.

Why a failed login is vague

An unknown address and a wrong password produce the same response, in the same amount of time. Nor does the API distinguish an expired token from a revoked one: all of it is a single 401 unauthorized. Telling those cases apart would confirm to an attacker which addresses are registered and whether a stolen credential was genuine.

Writing a template

Put placeholders anywhere in the document body, a header or a footer. Names are lowercase snake_case, and start with a letter. 

Dear {{.customer_name}},

Your plan is {{.plan}} at {{.amount}} per month.
Word splits your placeholders — that is handled

Word fragments a paragraph into runs for reasons of its own: a spell-check pass, an edit you made and undid, a stray formatting toggle. A placeholder you typed as one word routinely ends up stored as three fragments, and the literal text {{.customer_name}} appears nowhere in the file.

On upload, a normalisation pass reassembles each one. You do not need to retype anything, and the placeholder takes the formatting of its first character.

What is allowed

A placeholder is a bare field reference and nothing else. Pipelines, function calls, variables, conditionals and loops are rejected with an error naming exactly what was refused. The grammar is deliberately narrow because the template is untrusted input, and this is all the feature needs.

AcceptedRejected
{{.customer_name}}{{.CustomerName}} — must be lowercase
{{.line_1}}{{.customer.name}} — no nested fields
{{.amount}}{{if .name}}…{{end}} — no control flow
{{printf "%s" .name}} — no function calls

Values are escaped for you

A value containing &, < or > is escaped before substitution, so it appears literally in the finished document rather than corrupting its XML. Sending Acme & Sons <Ltd> is safe.

One limitation worth knowing: a newline inside a value does not become a line break in the document. Word needs explicit markup for that, which is not yet generated.

Template versions

Publishing a change never rewrites an existing version — it appends a new one. Every generated document records the exact version it came from, so a document made last month can still be reproduced after the template has moved on.

Generation uses the latest version unless you pin one with version. Pinning matters when you have already validated your payload against a specific schema and do not want a colleague's upload to change what your integration sends.

Deleting a template is a soft delete: it disappears from the API, but documents already generated from it stay downloadable.

Authentication endpoints

POST /v1/auth/register Public

Creates an account and returns it. This does not start a session — call /v1/auth/login next. Email is lowercased and trimmed before the uniqueness check.

POST /v1/auth/login Public

Exchanges email and password for a session.

200 OK
{
  "access_token": "eyJhbGciOiJIUzI1NiIs…",
  "token_type": "Bearer",
  "expires_at": "2026-09-08T21:12:06Z",
  "refresh_token": "PXhrICkLRqbVYB3KNBaa9YKZX813itfz6a_1ZNgVjVo",
  "refresh_expires_at": "2026-10-08T23:57:06Z",
  "user": { "id": "01a08374-…", "email": "someone@example.com", … }
}

401 for both a wrong password and an unknown address.

POST /v1/auth/refresh Public

Send refresh_token; receive a complete new session in the same shape as login. The secret you sent is now spent — replace both stored tokens.

401 if the secret is unknown, expired, revoked, or already consumed. In the last case every session of the account is revoked as well.

POST /v1/auth/logout Public

Send refresh_token to end that session. Always answers 204, whether or not the secret matched a live session: your intent is satisfied either way, and a different answer for an unknown secret would let this endpoint be used to probe for valid ones.

GET /v1/me

Returns the authenticated account. Useful for checking that a token is being sent correctly.

  "latest_version": 1,

  "version": {
    "id": "01a08374-6a08-749d-b6b8-9cd2fa9d2483",
    "version": 1,
    "size": 1379,
    "placeholders": ["amount", "customer_name", "plan"],
    "created_at": "2026-09-08T23:57:19Z"
  }
}

422 if the file is not a valid .docx, is missing word/document.xml, is too large, or uses a construct outside the placeholder grammar.

GET /v1/templates

Returns {"items": […]}, newest first. Takes limit (default 20, clamped to 100) and offset. Listed items omit version — fetch a single template to see its schema.

GET /v1/templates/{id}

Returns the template with its latest version. version.placeholders is the exact set of keys a generation request must supply — no more, no fewer.

POST /v1/templates/{id}/versions

Publishes a new version from an uploaded file part. The version number is allocated by the server, so simultaneous uploads cannot collide. Earlier versions remain usable.

DELETE /v1/templates/{id}

Soft delete, answering 204. Documents already generated from this template stay downloadable.

Keys must match the schema exactly

A missing key and an unrecognised key are both 422, and every problem is reported in one response rather than one round trip at a time. Rejecting unknown keys is deliberate: silently dropping a misspelled one would hand you a document missing text you believed you had supplied.

GET /v1/documents

Returns {"items": […]}, newest first, with the same limit and offset parameters.

GET /v1/documents/{id}

Returns the document's metadata, including the input data and the template version used — which together are what make the output reproducible.

GET /v1/documents/{id}/download

Streams the file. Range and conditional requests are supported.

Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document
Content-Disposition: attachment; filename="contract-acme.docx"
Cache-Control: private, max-age=31536000, immutable

A generated document never changes, so the response is marked immutable and can be cached indefinitely.

Errors

Every failure uses one shape, so a client needs a single error path. Branch on code, which is stable; message is prose and may be reworded. 

{
  "error": {
    "code": "validation_failed",
    "message": "the request could not be processed",
    "fields": [
      { "field": "data.amount", "message": "is required by the template" },
      { "field": "data.paln",   "message": "is not used by this template version" }
    ]
  }
}
StatusCodeMeaning
400bad_requestA path identifier is not a valid UUID.
401unauthorizedNo credential, or one that was not accepted. Carries WWW-Authenticate: Bearer.
404not_foundNo such resource for this account.
409conflictThe email address is already registered.
415unsupported_media_typeThe body was sent under an unexpected Content-Type.
422validation_failedWell formed, but not acceptable. The only code that carries fields.
429rate_limitedToo many requests. Carries Retry-After in seconds.
500internal_errorSomething failed on our side. Details are logged, never returned.
404 rather than 403

A resource belonging to another account is reported as missing, not forbidden. A 403 would confirm that the identifier exists, which is information the caller has no right to.

Rate limits

Three layers, each a token bucket. Refusals answer 429 with a Retry-After header in whole seconds, rounded up.

LayerKeyed byApplies toDefault
GlobalClient IPEvery request10/s, burst 60
CredentialsClient IP/v1/auth/*0.2/s, burst 10
WriteAccountUploading and generating2/s, burst 20

Because the global layer covers everything, any endpoint can answer 429. The strict limit on the credential routes is what makes password guessing impractical: after ten attempts you are waiting five seconds per try.

The client IP is taken from the connection. X-Forwarded-For is honoured only when the deployment declares that a trusted proxy sets it — otherwise any client could choose its own rate-limit key by sending a header.

Health

GET /healthz Public

Answers {"status":"ok"} when the database is reachable, and 503 when it is not. It is public, but not exempt from the global rate limit.
